# Review queue

## What belongs here

Use the queue for incorrect names, stale ownership, missing relationships, duplicate entities,
misleading code dependencies, and Wiki rewrite requests.

## What happens next

1. A human selects an entity, relation, code symbol, or Wiki page.
2. Boron records the proposed fields and instruction as `pending` evidence.
3. A later agent compares the request with the current ontology, repository, and documentation.
4. The agent applies or rejects the semantic repair and records a resolved or dismissed outcome.

The queue is an audit surface, not a second source of truth.
