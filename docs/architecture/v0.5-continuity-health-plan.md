# v0.5 continuity health plan

## Product outcome

Boron should disappear into normal project work: a supported coding agent starts with the right
project context, keeps one durable session alive while meaningful work continues, and closes it
without requiring the user to manage a second system. The result is smoother continuity, not model
training and not passive conversation surveillance.

## Product contract

1. **Invisible when healthy.** A Codex task uses `CODEX_THREAD_ID` to resume one leased Boron
   session. The user should not need to copy IDs or repeat project context.
2. **Honest observability.** Coverage uses MCP-initialized agent threads as its denominator. Agents
   that never load the plugin are outside observability; the product never labels them covered.
3. **Fail-safe closure.** A missing explicit completion becomes an auditable `partial` after the
   lease expires, never an indefinitely active session and never a fabricated completed outcome.
4. **One durable identity.** Exact roots and normalized Git remotes may deterministically identify a
   project. Ambiguous name-only matches remain candidate or fail closed. Explicit supersession
   preserves historical rows and provenance.
5. **Readable truth.** A confirmed relation confirms that its non-rejected endpoint entities exist.
   This reduces candidate noise without upgrading unrelated candidate relationships.
6. **Current sources first.** Local Codebase Memory and OpenWiki are queried live when healthy;
   PostgreSQL snapshots remain labeled fallback. Source-window savings use only real source-size
   estimates.

## Implementation slices and acceptance

| Slice             | Acceptance                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Agent adoption    | MCP initialization is recorded without transcript content; context read/session coverage and caveats are queryable.                              |
| Session lifecycle | Repeated begin in one active Codex thread resumes; activity renews the lease; expired work closes once as `partial`.                             |
| Project identity  | Temporary clones sharing one Git remote converge; approved Lofi Mojo and NotionNext fragments merge; retired TingCheng identities archive.       |
| Ontology clarity  | No confirmed current relation connects to a candidate endpoint after repair; candidate relations remain visible and reviewable.                  |
| Live retrieval    | Health exposes live Codebase Memory and OpenWiki adapters; a routed query records `sourceType=live` and real source estimates where files exist. |
| Operations        | Migration and supersession are previewable, backed up, idempotent, tested, and verified after daemon/plugin restart.                             |

## Human boundary

The agent may automatically renew sessions, close expired sessions as partial, normalize a Git
remote, and use exact user-approved supersession entries. A person is still required to approve an
uncertain project merge, a candidate semantic relationship, a high-risk action, or publication.

## Cost and performance target

- Boron-owned LLM calls: `0`.
- Local daemon idle memory target: below `100 MB` RSS.
- Average context retrieval target: below `100 ms` for local sources.
- Background sweep: once per 5 minutes; no polling faster than needed.
- External service cost: `$0/month` for the default local configuration.
