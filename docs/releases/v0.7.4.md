# Boron Context v0.7.4 — Governed ontology writeback

Version 0.7.4 introduces ontology governance contract v1 without rewriting historical facts. It is
an additive productization milestone for macOS + Codex and does not authorize public release or
Marketplace submission.

## Contract

- `ontology_type_registry` classifies entity kinds and relation types as active, legacy, or
  deprecated and records owner, source authority, source URI, and optional replacement.
- migration 011 labels existing objects, relations, and relation effects as contract v0. Their
  observed vocabulary is registered as legacy; semantic payloads are unchanged.
- new activity relation writeback uses contract v1. Unknown kinds and relation types fail closed,
  agent inference cannot directly confirm a relation, and retraction requires an active relation.
- deprecated registered vocabulary remains compatible but emits deprecated decisions and
  replacement metadata.

## Audit surfaces

- `POST /v1/metrics/ontology-governance` and `get_ontology_governance_health` report contract
  version, registry status/source-authority counts, accepted/rejected/deprecated decisions and
  reasons, and stored contract-v1 versus contract-v0 boundaries.
- activity responses add a backward-compatible `ontologyGovernance` summary.
- the authenticated Inspector renders 30-day governance counts next to 7/30-day adoption and
  writeback eligibility.

## Verification scope

The release gate includes Node/TypeScript and formatting checks, production dependency audit,
native Swift tests/build, plugin payload validation, and a temporary PostgreSQL 17 database with
fixtures for known, unknown, deprecated, candidate, confirmed, manual-correction, cross-project,
retraction, and legacy rows. Production data is migrated only after the pull request and main CI are
green.

## Remaining release-candidate gates

This milestone does not establish product readiness. The held-out continuity recall@5 evaluation,
source-estimate coverage target, mature 7-day eligible-adoption sample, isolated
install/upgrade/uninstall/rollback drill, and formal release checklist remain open.
