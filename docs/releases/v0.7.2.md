# Boron Context v0.7.2 — Fail-closed session scope

Version 0.7.2 closes the remaining project-identity drift path in resumable Codex sessions and
packages the post-v0.7.1 integrity and plugin-cache safeguards as one auditable patch release.

When a client reuses an external session ID, Boron now compares the requested project with the
persisted project before renewing the lease or updating session metadata. A different project is
rejected with `project_mismatch`; the existing session remains owned by its original project. A
same-project alias still resumes the canonical persisted identity, and previously unscoped sessions
can adopt a newly resolved project once.

The release also includes explicit project-scoped activity writeback, future-timestamp rejection,
independent-project registry support, structured context-quality health, and deterministic Codex
plugin payload cache keys that landed after v0.7.1.

## Verification
