# Boron Context v0.5.0 — Continuity health

Version 0.5.0 makes Boron quieter and more dependable in normal agent work. Supported clients can
reuse one task-scoped session, abandoned work closes safely, project identities converge without
losing history, and live sources remain explicitly distinguishable from stored snapshots.

## What changed

- `CODEX_THREAD_ID` becomes the default external session identity in the bundled Codex plugin.
- Sessions use a renewable 12-hour lease. Expired work closes once as `partial` with auditable
  provenance instead of remaining active indefinitely.
- MCP initialization creates a content-free adoption observation. Coverage reports only the agent
  tasks Boron can actually observe and never claims visibility into clients that did not load it.
  The observation path times out after 500 ms and never blocks normal work on a telemetry failure.
- Unknown Git worktrees converge on a normalized, credential-free remote URI. Explicit
  user-approved supersession manifests merge or archive historical project identities without
  deleting their rows.
- Confirmed, non-model-proposed relations confirm that their non-rejected endpoint entities exist;
  candidate relations remain candidate.
- Noncanonical aliases remain candidate; migration `008` reverses any overly broad local alias
  confirmation from the initial `007` application while preserving its audit metadata.
- Codebase Memory `/rpc` and project-scoped OpenWiki Markdown are queried live by default, with
  labeled PostgreSQL evidence snapshots retained as fallback.
- Context Meter project filters resolve canonical aliases before aggregation, and source-window
  savings still require real source-size coverage.

## Product boundary

Boron is a deterministic local context substrate, not a conversation logger or a model-training
system. It stores selected verified milestones, decisions, evidence, and typed relation changes.
It does not capture raw chats or claim coverage for agents that never initialize the plugin.

## Upgrade

```bash
npm ci
npm run db:migrate
npm run check
npm run service:install
python3 scripts/install_menubar.py
codex plugin add boron-context@boron-context
```

Start a new Codex task after reinstalling the plugin so its v0.5 MCP tools and continuity skill are
loaded.
