# Boron Context v0.7.3 — Honest telemetry denominators

Version 0.7.3 replaces the ambiguous adoption/writeback denominator with a backward-compatible,
reason-coded eligibility contract for macOS + Codex product health.

## Contract

- `get_adoption_health` and `POST /v1/metrics/adoption` return `contractVersion: 2`.
- `adoption` reports its numerator, eligible denominator, ratio, ineligible observations,
  unobservable Codex tasks, and reason maps.
- `writeback` reports explicitly project-verified semantic activities over its eligible semantic
  denominator, plus lifecycle/intent and legacy exclusions.
- read-only context is adoption-eligible and writeback-ineligible.
- automatic lifecycle-only sessions and MCP-initialization-only observations are not treated as
  semantic work.
- Codex task IDs without a matching hook/MCP observation are `unobservable`, never failures or
  denominator members.

The historical top-level mixed fields remain unchanged for older clients. Contract-v1 rows are
labelled as legacy by migration 010; Boron does not rewrite their semantic payloads.

## Surfaces

- HTTP API and MCP expose the same v2 fields and reason names.
- The authenticated local Inspector shows 7-day and 30-day adoption/writeback cards.
- English and Chinese operating manuals define the denominator and the compatibility boundary.

## Verification scope

- unit and gateway contracts;
- hook and MCP source tagging;
- temporary PostgreSQL fixtures for semantic, lifecycle-only, read-only, legacy implicit,
  hook/MCP-only, and unobservable tasks;
- Node/TypeScript, Swift, formatting, plugin payload, package, and production dependency gates.
