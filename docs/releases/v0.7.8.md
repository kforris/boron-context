# Boron Context v0.7.8 — Vision-grounded repository retrieval

Version 0.7.8 makes Boron better at answering the project's own vision, roadmap, architecture, and
operational questions from confirmed repository documents. It is a bounded local iteration and
does not authorize a public release, Marketplace submission, push, deployment, or lifecycle work.

## Acceptance contract

- the live wiki layer searches Markdown in confirmed registered project roots as well as OpenWiki;
- traversal is deterministic and bounded to 200 files and 200 directories, skips generated,
  dependency, VCS, and vendor directories, ignores files larger than 256 KiB, and does not follow
  directory symlinks;
- exact Markdown anchors route to the wiki layer and receive deterministic ranking priority;
- every live adapter in a selected non-ontology layer is attempted before one snapshot fallback is
  considered, while wrong-project evidence is filtered before ranking and packing;
- local repository documents retain auditable file-size provenance using the existing `bytes / 4`
  estimate;
- English and Chinese read-only release assessment stays standard risk, but actual deploy, publish,
  push, execute, or other mutation intent still requires the high-risk policy stage; and
- focused unit tests plus the full regression suite cover source bounds, exact anchors, multi-live
  routing, fallback behavior, bilingual intent, and risk classification.

## Production-shaped evidence

The new 18-case deterministic repository suite uses checked-in Markdown, synthetic Ontology
responses, no private data, and zero Boron-owned LLM calls. The frozen 0.7.8 results are:

| Metric                        | Result   | Minimum |
| ----------------------------- | -------- | ------- |
| Recall@5                      | 0.888889 | 0.80    |
| Mean reciprocal rank          | 0.736111 | 0.60    |
| Relevant-source size coverage | 0.888889 | 0.80    |
| Routing accuracy              | 1.00     | 1.00    |
| Risk-classification accuracy  | 1.00     | 1.00    |
| Wrong-project retrieval       | 0        | 0       |

This complements the original six-case synthetic held-out suite; it does not replace live adoption
or source-coverage measurements.

## Remaining product gates

The live 7-day and 30-day eligible-source coverage gate remains separate and may still be below the
80% release-candidate target. The 0.8 macOS install, upgrade, uninstall, backup, restore, and
rollback rehearsal also remains intentionally untouched. Public release still requires a separate
human go/no-go decision after those gates pass.
