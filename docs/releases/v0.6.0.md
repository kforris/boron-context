# Boron Context v0.6.0 — Invisible Codex continuity

Version 0.6.0 moves project context from a model-selected workflow toward a Codex lifecycle
default. After one explicit hook trust review, starting a Codex task automatically opens or resumes
one project-scoped Boron session and adds a bounded, sourced Capsule to developer context.

## What changed

- The plugin bundles `SessionStart` and `SessionEnd` hooks using Codex's documented lifecycle hook
  contract.
- `SessionStart` incrementally imports privacy-safe task ownership into a dedicated Boron index. It
  never rewrites Codex private state or creates hundreds of task nodes in the Ontology graph.
- Automatic bootstrap requires an exact project scope. Broad home roots and unresolved projects do
  not create an unscoped session.
- Startup sends only the Codex session ID, exact working directory, and lifecycle source. It never
  reads or forwards the user prompt or transcript.
- Hook output is capped, source-labeled, and explicitly treated as evidence rather than instruction.
- Normal agents still call `complete_context_session` with verified outcomes. `SessionEnd` only
  closes a remaining active lease as `partial`, and repeated finalization is a no-op.
- Hook failures time out and fail open so Boron cannot prevent Codex from running.
- Agent lifecycle and activity mutations require the daemon bearer; the Inspector browser session
  remains limited to its CSRF-protected human-correction workflow.
- A local reviewer can produce an explicitly approved historical plan, but it is read-only and
  sends only IDs, classifications, authority, confidence, and evidence digests to Boron.
- Equal-authority ownership conflicts fail closed. Unknown temporary roots never auto-create a
  confirmed project.

## Trust boundary

Codex requires users to review and trust new or changed command hooks. After installing the plugin,
inspect the exact two commands in a Codex surface that exposes hook review (`/hooks` in the CLI),
then start a new task. A desktop build without `/hooks` can use the same local trust decision; verify
that the fresh task contains `Boron automatic project context`. The MCP tools and skill remain usable
as the fallback.
