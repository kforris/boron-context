# Boron Context v0.8.0 — Rehearsable macOS lifecycle

Version 0.8.0 makes the source-installed macOS + Codex lifecycle auditable and recoverable. It adds
safe PostgreSQL backup/restore helpers, reversible uninstall behavior, isolated launchd/menu labels,
and one receipt-producing rehearsal covering install, upgrade, restore, rollback, and uninstall.

This milestone reaches the lifecycle/checklist portion of the release-candidate boundary. It does
not authorize a public release, Marketplace submission, signing/notarization, payment, or marketing.

## Acceptance contract

- backup refuses to overwrite a path, writes a PostgreSQL custom-format archive with mode `0600`,
  and records byte size plus SHA-256 in a credential-free receipt;
- restore requires `--confirm-empty-target`, verifies an optional SHA-256, rejects any target with
  user objects, and restores without owner or privilege replay;
- uninstall removes only launchd plists/services, the menu app, and explicitly selected Codex
  registrations; it never drops a database or deletes the token/state/log directories;
- daemon, LAN MR, and menu labels can be overridden for isolated rehearsal while production defaults
  remain backward compatible;
- generic changelogs and release checklists no longer outrank the requested roadmap or privacy
  document unless the request asks for changes, release gates, readiness, or an exact source;
- the rehearsal uses temporary HOME, CODEX_HOME, PostgreSQL, ports, labels, and marketplace state;
  it upgrades from the frozen 0.7.8 main commit and rolls all artifacts plus data back; and
- a formal checklist separates lifecycle evidence from CI, quality, security, live product health,
  and the final human release decision.

## Verified rehearsal

The 2026-08-19 macOS rehearsal completed 29/29 steps in 62.697 seconds. It clean-installed and
uninstalled 0.8.0 while preserving its migrated database, then installed 0.7.8, upgraded to 0.8.0,
preserved a database sentinel, restored the SHA-256-verified backup into an empty database, rolled
database/daemon/menu/plugin back to 0.7.8, and uninstalled all temporary runtime surfaces while
retaining durable data. The receipt reported
`productionDatabaseTouched=false`; no rehearsal launchd or PostgreSQL process remained.

## Supported boundary and remaining gate

The release candidate is a source installation for Apple Silicon macOS 14+, Node.js 20.19+, and
PostgreSQL 15+ with Codex local marketplace support. Linux packaging, Intel macOS, a signed binary
installer, hosted/multi-user operation, and automatic hook trust are not claimed.

Lifecycle completion does not substitute for live health. The go/no-go review must still verify the
current 7-day eligible adoption, selected-source eligible coverage, recall@5, latency, wrong-project
counts, P0/P1 count, corrections, and zero Boron-owned LLM calls against
[`docs/release-checklist.md`](../release-checklist.md).

The final 18-case production-shaped evaluation is recall@5 `0.888889`, MRR `0.768519`, relevant
source coverage `0.888889`, routing/risk accuracy `1.00`, and wrong-project retrieval `0`. The frozen
0.7.8 MRR remains `0.736111`; it was not lowered or rewritten.
