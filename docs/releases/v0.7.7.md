# Boron Context v0.7.7 — Truthful external source sizing

Version 0.7.7 improves selected-source size instrumentation for macOS + Codex without turning
telemetry into a new content reader. It remains a productization milestone and does not authorize
public release, Marketplace submission, paid activity, or marketing.

## Acceptance contract

- newly recorded evidence that explicitly references a supported local text `file://` URI inside
  the current project's confirmed registered roots is measured from file metadata using an
  auditable `bytes / 4` basis;
- Boron does not read the file body for this measurement and does not fetch remote URLs merely to
  improve coverage;
- local directories are labelled `local_directory_reference` and excluded because a directory is
  not an original source window;
- missing, inaccessible, non-local, or unsupported local paths and unfetched remote sources remain
  unmeasured with specific reason labels;
- paths outside confirmed registered roots are not inspected and report an explicit unavailable
  reason;
- callers may continue to provide a real `sourceTokenEstimate`; old inputs, API responses, and
  historical records remain compatible and are not rewritten; and
- unit plus temporary-PostgreSQL fixtures cover measured local text, directories, and remote
  no-fetch behavior.

## Product-health interpretation

This release improves future eligible samples. It does not backfill old evidence or convert an
unobserved remote page size into a measurement, so 7-day and 30-day coverage may remain below the
release-candidate threshold until enough truthful new samples accumulate.
